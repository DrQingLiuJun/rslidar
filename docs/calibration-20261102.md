# 三雷达外参标定与验证（2026-11-02）

已修改服务器 `/home/user/carla-projects/rslidar_ws`，重启三路检测和RViz，完成现场TF、点云、检测输出检查。经纬度采用用户提供的三处安装点，ENU参考点沿用项目原值：经度113.6800472、纬度34.5878275。模型权重、原始模型输入坐标、端口、跟踪逻辑以及之前修复的DDS缓冲均保留。

## 原因

原配置仅有XY平移和偏航角，三路高度都为0、横滚俯仰都为0。39号偏航使用129.360°，实际与36号方向不同；41号偏航为默认0°，其地面回波位于传感器本地Z轴正侧，安装呈倒置，需要接近180°横滚。仅改变RViz观察角度不能修复这些外参问题。

原检测文字中的经纬度与航向还另行使用纯二维变换；即便只调整TF使点云对齐，倒装雷达的经纬度、朝向文字仍会错误。因此补全共享三维外参，并让TF与检测文字使用相同的旋转、平移和ENU原点。检测框保留在原始传感器坐标系中，由TF做一次变换，避免重复旋转。

## 方法与证据

1. 读取正在运行的三路原始点云，采集两个连续独立6秒时段，每路每时段8帧。第一时段求解，第二时段仅验证；剔除非有限值，并进行体素采样。
2. 从地面主平面估计安装倾斜和相对高度；识别41号的Z方向翻转。
3. 在经纬度基线约束下进行全周偏航搜索，静态非地面结构配准；继而做有限门限的三维刚体精配准。两台80线雷达拟合基线长度与经纬度基线长度相差约4厘米。
4. 在独立时段检查非地面结构，保存实际原变换与新变换的对比图。主要共视连接为36↔39、39↔41；36↔41直接共视很有限，不能把没有共同可见面的点也解释为配准误差。
5. 对现场`/tf_static`逐一读取，比对配置计算的三维旋转和平移；三个父坐标系均为map，平移差0、旋转矩阵最大数值差约3.3e-16。
6. 10项回归检查全部通过，包含倒装雷达、三维TF、地理标签一致性及原有配置和跟踪行为。上线后再采集30秒，点云三路均10Hz，检测分别约2.96、2.95、3.04Hz。

独立时段在“非地面点到另一台雷达的最近邻距离小于1米”这个明确筛选条件下，39→36候选对应点9763个，中位距离0.193米、P90为0.704米；41→39候选对应点1024个，中位距离0.178米、P90为0.754米。该指标只描述筛选后的结构候选点，不能当成全场景误差、动态目标中心误差或真值测量精度。

全体几何共视范围点的统计另见`validation.json`。其中39→36非地面点最近邻中位距离从约21.71米降至1.69米，41→39从29.94米降至0.295米。不同可见面、遮挡、树叶和扫描密度会显著影响全体点的统计，故不能挑选筛选指标冒充全部点的精度。

## 代码与配置

- `src/lidar_perception/config/sensors.yaml`：三台经纬度、水平小修正、高度、横滚、俯仰、偏航。
- `src/lidar_perception/lidar_perception/geometry.py`：共享三维外参、ENU与经纬度转换、方向投影。
- `src/lidar_perception/launch/perception.launch.py`：将完整外参传给静态TF及检测器，共用参考点。
- `src/lidar_perception/lidar_perception/detector_node.py`：读取新增安装参数，传给可视化；原始点云仍按训练坐标进入模型。
- `src/lidar_perception/lidar_perception/visualization.py`：经纬度及方向文字采用完整三维变换，检测框维持本地坐标，通过TF显示。
- `config/three_lidars.rviz`：调整初始视点并标明点位与IP。
- `tests/test_geometry.py`：三维变换、翻转、兼容性与标签一致性检查。

## 精度边界与后续

本次纠正了大角度错位、倒置和高度缺失，静态共视结构已明显改善。没有人工逐目标真值，也没有独立RTK/全站仪测量，不能声称已达厘米级绝对定位，或每个动态目标的多个检测框必然完全重合。两组点云来自短时间现场采集，仍应在更多位置和时段复核。

动态目标的误差还包含扫描相位/时间差、不同视角下的检测框中心偏差、遮挡和模型误检漏检。本次不通过移动单个检测框或扭曲点云去制造重合，也未增加跨雷达身份融合。若后续需要严格量化，应让带位置/时间参考的同一目标经过三台共视区，按同步时间比较中心、方向和速度，再决定是否需要时间补偿或检测框中心校正。
